The Keepers of the Secret

"Every Founding Father had a role. Every agent has a keeper."

Each agent has its own hook mechanism for the adversary review layer. The deterministic layers (network, exec, files) work universally — sandpit run handles those. But the LLM reviewer needs to be wired into each agent's tool-call pipeline.

pi

Mechanism: In-process TypeScript extension using completeSimple()

Review model: Whatever provider/model pi is configured with

sandpit install pi
sandpit run -- pi

Installs ~/.pi/agent/extensions/adversary.ts and writes your rules to ~/.pi/agent/adversary.md. The extension intercepts every bash tool call and runs it past the model before execution. Active by default once installed — disable with pi --no-adversary.

Goose

Mechanism: Built-in AdversaryInspector that reads rules from a known path

Review model: Whatever provider model Goose is configured with

Overhead: ~2.9s/call

sandpit install goose
sandpit run -- goose session

Writes your rules to ~/.config/goose/adversary.md. Goose's built-in inspector picks this up automatically and reviews tool calls inline. Delete the file to disable.

Claude Code

Mechanism: PreToolUse prompt hook — Claude reviews its own tool calls inline

Review model: Haiku (automatic, no configuration needed)

Overhead: ~2.3s/call

sandpit install claude
sandpit run -- claude

Adds a PreToolUse hook to ~/.claude/settings.json. When Claude Code is about to run a Bash command, the hook fires a prompt that asks haiku to review the command against your policy. If the review returns "deny", the tool call is blocked.

This is the most elegant integration — no subprocess, no external script. Claude reviews itself using a smaller, faster model.

Amp

Mechanism: Delegate permission → Python review script → amp -m rush -x

Review model: Rush mode (fast, lightweight)

Overhead: ~0.9s/call ⚡

sandpit install amp
sandpit run -- amp

Installs two things:

  • ~/.sandpit/amp-review.sh — a Python script (despite the extension) that receives JSON from amp's permission system, extracts the command, assembles a review prompt, and pipes it to amp -m rush -x via stdin
  • A delegate permission in ~/.config/amp/settings.json that routes all Bash tool calls through the script

The review amp instance uses a separate ~/.sandpit/amp-review-settings.json (empty config) to avoid infinite recursion — the reviewer itself has no sandpit permissions, so it won't trigger another review.

Security note: The command string is never interpolated into a bash string. It flows from JSON stdin → Python variable → subprocess stdin to amp, avoiding shell injection entirely.

Codex

Mechanism: None — deterministic layers only

sandpit run -- codex

Codex has no pre-execution hook API. The DYLD interpose and seatbelt layers still work — network, exec, and file enforcement are fully active. But there's no adversary LLM review of individual tool calls.

Performance Comparison

Measured on 10 sequential Bash tool calls (mkdir, echo, curl, wc, grep, find, cat, ls):

Agent With Adversary Without Overhead Per Call
Claude Code 37.8s 14.4s +23.4s (+162%) ~2.3s
Goose 72.5s 43.6s +28.9s (+66%) ~2.9s
Amp 42.2s 33.2s +9.0s (+27%) ~0.9s

Amp's rush mode is the fastest by a wide margin. Claude's haiku hook is next. Goose uses the full provider model so it's the slowest but also the most capable reviewer.
